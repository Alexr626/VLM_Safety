# git archive vs gitignore, and COCO location on NFS

**Date:** 2026-06-25

## Does `git archive` include gitignored files?

**No.** `git archive` only packs **tracked** files (what `git ls-files` would list at that commit). Anything in `.gitignore` that is not force-added with `!` exceptions is **omitted**.

### Included in current archive (examples)

- All source, `environment.yml`, `helper_scripts/runai/*` (incl. `run_smoke_pope.sh`)
- `data/pope/pinned_eval_ids.json`, `data/pope/combined.json`, POPE output JSONs
- `data/vti/demos.jsonl`
- `data/coco/.gitkeep` only (placeholder — **not** images)

### NOT included (gitignored)

| Category | Examples | On RunAI |
|----------|----------|----------|
| **COCO images** | `data/coco/val2014/`, `train2014/` | Downloaded by `setup_vlm.sh` → on NFS |
| **CHAIR manifest** | `data/chair/combined.json` | Built by `download_chair.py` during setup |
| **CHAIR/AMBER pinned subsets** | `data/chair/pinned_chair_500.json`, `data/amber/pinned_amber_disc_450.json` | Generated by `draw_subsets.py` on first run (or run `run_prep_subsets.sh`) |
| **Eval results** | `evaluation/results/` | Written by jobs on NFS |
| **Agent docs** | `IMPLEMENTATION.md`, `RESEARCH_LOG.md`, `answers/` | lambdab2 only unless copied manually |
| **HF weights** | model checkpoints | `hf_cache/` on NFS from setup |

### Rule of thumb

- **Code + small manifests** → tarball via `git archive`
- **Large binaries** → download on NFS during setup or first job (COCO, HF weights)
- **Generated subsets** → run prep script once on NFS (or let exp scripts auto-draw)
